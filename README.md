# MASP LAN Benchmark

Browser bench harness for two workloads on the same page:

1. **2x2 Groth16 proving** — `ark-circom` Rust prover compiled to WASM
   (rayon multi-threaded) inside a module Web Worker. Witness generation
   stays JS-side via the circom-emitted `witness_calculator.js`.
2. **Wallet scan throughput** — SDK `scanNotes` over a synthetic batch of
   FMD-flagged encrypted notes, driven by `WasmJubjub`. Bundled with esbuild
   into a single worker (`bench.scan.worker.js`).

Server binds `0.0.0.0`; any device on the same Wi-Fi opens the URL, hits the
buttons, and posts timings back.

## Layout

```
bench/
├── server.ts                  # static server + COOP/COEP + self-signed cert
├── prepare.ts                 # builds public/input.json (canonical witness)
├── src/
│   ├── scan-worker.ts         # entry for esbuild-bundled scan worker
│   └── circomlibjs-stub.js    # alias to keep node-flavored deps out of bundle
├── public/
│   ├── index.html             # both panels (proof bench + scan bench)
│   ├── bench.js               # proof bench UI
│   ├── bench.ark.worker.js    # ark-circom worker (loads /prover/* + zkey)
│   ├── scan-bench.js          # scan bench UI
│   ├── bench.scan.worker.js   # generated by scan-build (gitignored)
│   ├── jubjub_wasm_bg.wasm    # generated by scan-build (gitignored)
│   └── input.json             # generated by prepare
├── prover-pkg/                # generated by prover-build (gitignored)
└── justfile                   # all recipes
```

The Rust prover crate lives at `sdk/wasm/prover/`; `prover-build` runs
`wasm-pack` there and copies output into `bench/prover-pkg/`. The scan
worker pulls SDK sources directly via esbuild and depends on the jubjub
wasm crate at `sdk/wasm/jubjub/` (built by `scan-build`).

## Prereqs

- Node + npm (for ts-node).
- Rust nightly + `rust-src` component (pinned in `sdk/wasm/prover/rust-toolchain.toml`).
- `wasm-pack` on PATH (the recipe auto-installs via `cargo install wasm-pack` if missing).
- `openssl` on PATH (only for HTTPS mode — used to mint the self-signed cert).
- Circuit artifacts at `circuits/build/`: `2x2_final.zkey`, `2x2_js/2x2.wasm`,
  `2x2_js/witness_calculator.js`. Build them with the circuits package's own
  recipes before running the bench.

## Launch

All recipes run from `bench/`.

```bash
cd bench
just install            # one-time: ts-node + types
just prepare            # one-time: generate public/input.json
just prover-build       # builds Rust prover wasm, copies into bench/prover-pkg/
just scan-build         # builds jubjub wasm + bundles scan worker into public/
just serve              # HTTPS bench server on :8787
```

`prover-build` is required for the proof bench panel; `scan-build` is
required for the scan bench panel. Run whichever you intend to use (or both).

Server prints LAN URLs:

```
local:    https://localhost:8787
lan:      https://192.168.1.42:8787
```

Open on each device. Two panels:

- **Run benchmark** — 2x2 Groth16 proof, 5 iters + warm-up. Per-device runs
  (timings + worker debug events) append to `bench/results.json`.
- **Run scan benchmark** — wallet scan over `N` synthetic notes with a
  configurable mine percentage. Reports `hits`, `totalMs`, per-note ms, and
  notes/s. Results stay client-side (no POST).

Override port: `just serve PORT=9000`.

## Scan bench notes

- `scan-build` runs `just jubjub-build` in `sdk/wasm/`, then esbuilds
  `src/scan-worker.ts` (bundling SDK sources) into
  `public/bench.scan.worker.js` and copies `jubjub_wasm_bg.wasm` next to it.
- `circomlibjs` is aliased to a stub (`src/circomlibjs-stub.js`) — its
  node-flavored deps (`assert`/`buffer`/`events`) would balloon the bundle by
  megabytes. Synthetic notes use `WasmJubjub` primitives directly.
- Re-run `just scan-build` after editing `src/scan-worker.ts` or `sdk/src/**`.
- Warm-up scans the first 50 notes before the timed run (JIT, wasm pages).

## Why HTTPS

The Rust prover is multi-threaded via `wasm-bindgen-rayon`, which needs
`SharedArrayBuffer`. Browsers gate SAB on **cross-origin isolation**, which
only works in a **secure context** (HTTPS or `localhost`). Plain HTTP over a
LAN IP is *not* a secure context — mobile Safari falls back to single-thread
and the prover runs ~3-4× slower than it should.

The server already sets the required headers
(`Cross-Origin-Opener-Policy: same-origin`,
`Cross-Origin-Embedder-Policy: require-corp`,
`Cross-Origin-Resource-Policy: same-origin`); HTTPS is the missing piece for
LAN devices.

## Self-signed cert

`just serve` enables HTTPS. On first run, `bench/server.ts` mints a
self-signed cert into `bench/.certs/`:

- `key.pem` — RSA 2048 private key
- `cert.pem` — X.509 cert, 365-day validity, CN=`lelantos-bench`
- `openssl.cnf` — config used by the openssl invocation
- SubjectAltNames cover `localhost`, `127.0.0.1`, and every detected non-internal
  IPv4 LAN address at generation time

If the LAN IP changes (new Wi-Fi, etc.), regenerate by deleting the dir:

```bash
rm -rf bench/.certs
just serve   # mints fresh cert against current LAN IPs
```

### Trusting the cert on iPhone Safari

Self-signed certs trigger a Safari warning. To allow the page to load (and
crucially, to enable cross-origin isolation):

1. Visit `https://<lan-ip>:8787/` once on the iPhone. Safari shows a
   "This Connection Is Not Private" page.
2. Tap **Show Details** → **visit this website** → **Visit Website** in the prompt.
3. Reload the page. Run the bench. The on-page log should show:
   ```
   [worker:init-start] {"isolated":true, ...}
   [worker:threadpool-done] {"ms":...}
   threads=4 isolated=true
   ```
   If `isolated=false` shows up, threading is off — re-check that you're on
   `https://` and that the cert was accepted for this exact IP+port.

For desktop Chrome/Firefox: same flow — accept the cert warning once per
browser/origin.

### Persistent trust (optional)

If repeated cert warnings get annoying:

- **macOS Safari**: open `cert.pem` from `bench/.certs/` in Keychain Access
  → set "Always Trust" for SSL.
- **iPhone**: AirDrop `cert.pem` to the device → Settings → General → VPN &
  Device Management → install profile → Settings → General → About → Certificate
  Trust Settings → enable full trust for "lelantos-bench".

## Plain HTTP fallback

```bash
HTTPS=0 ./node_modules/.bin/ts-node server.ts
```

Works for `localhost` testing only. LAN devices will fall back to single-thread
and the bench will print:

```
[worker:threadpool-skipped] {"isolated":false}
```

## Troubleshooting

| symptom | cause | fix |
|---|---|---|
| `[worker:threadpool-skipped] isolated:false` | not in secure context | use HTTPS or localhost |
| `Failed to fetch dynamically imported module: /prover/` | pkg not built / not copied | `just prover-build` |
| `Memory could not be cloned` (during prepare) | wasm not built with shared memory | rebuild — pinned nightly handles this |
| cert warning on every fresh device | self-signed | trust manually (see above) or use `mkcert` for a locally-trusted CA |
| `WARN: missing prover-pkg` at server start | pkg copy missing | `just prover-build` |
| scan panel: `worker error` / 404 on `/bench.scan.worker.js` | bundle not built | `just scan-build` |
| scan panel: silent / no log output | second `$`/`log` global collision (older bench.js) | hard-reload; scan-bench.js is IIFE-wrapped |

## Notes

- Warm-up iter not counted (covers wasm/zkey download, JIT, thread-pool spin-up).
- 29 MB zkey downloads once per device; browser caches it after first hit.
- 5 iters per run, hardcoded.
- `results.json` is JSONL; safe to `tail -f` while iPhones run.
- Edit `public/bench.js` / `public/index.html` for UI changes — server
  serves with `Cache-Control: no-store` for HTML/JS so a reload picks them up.
- Edit `sdk/wasm/prover/src/` and rerun `just prover-build` to refresh the wasm.
- Edit `bench/src/scan-worker.ts` or `sdk/src/**` and rerun `just scan-build`
  to refresh the scan worker bundle.
